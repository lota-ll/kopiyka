# ADR-0005. Портабельність між хмарними провайдерами

* Статус: прийнято
* Дата: 2026-08-03

## Контекст

Наявний AWS-тріал діє обмежений час. Після його завершення типовий
«правильний» AWS-стек (NAT Gateway, ALB, RDS, Fargate) коштує близько
70–75 USD на місяць — неприйнятно для особистого проєкту, яким автор
користується щодня.

## Рішення

Два незалежні цільові середовища з єдиною кодовою базою:

* **AWS** — демонстраційне середовище, піднімається на час і знищується
  (`tofu destroy`) після кожної сесії.
* **VM (Hetzner / Oracle Always Free)** — постійне середовище.

Портабельність забезпечується чотирма правилами:

1. Застосунок читає **тільки env-змінні**; знання про провайдера в коді
   відсутнє.
2. Об'єктне сховище — через S3 API з конфігурованим `endpoint_url`
   (S3 / R2 / MinIO / B2).
3. Модулі OpenTofu `providers/aws/` і `providers/hetzner/` експортують
   **однаковий набір outputs**; root-модуль перемикається змінною.
4. Усе, що не є «контейнер + PostgreSQL + S3-сумісне сховище + HTTP
   ingress», вважається lock-in і потребує окремого рішення.

## Обґрунтування

Managed-сервіси (Lambda, DynamoDB, Cognito, SQS) покращили б демонстрацію
на AWS, але зробили б перенесення переписуванням застосунку.

## Наслідки

* Свідома відмова від низки зручних AWS-сервісів.
* Секрети — SOPS + age у git, а не AWS Secrets Manager (провайдер-нейтрально
  і безкоштовно).
* Реєстр образів — GHCR, не ECR.
* Портабельність вважається доведеною лише після **фактичного розгортання
  на обох провайдерах**; час розгортання з нуля фіксується в README.
  Декларація без цього кроку нічого не варта.
