# Безпека

Система обробляє банківські виписки кількох домогосподарств. Це визначає
модель загроз і перелік інваріантів, які перевіряються автоматично.

## Модель загроз (скорочено)

| Загроза | Наслідок | Контроль |
|---|---|---|
| Cross-tenant доступ (IDOR) | Витік чужої фінансової історії | RLS + `ROUTE_MATRIX`-тест у CI |
| Компрометація ролі застосунку | Доступ до всіх тенантів | Роль без `BYPASSRLS`, не власник таблиць |
| Витік сирої виписки з object storage | Повна історія операцій | Невгадувані ключі, presigned URL 5 хв, TTL 7 днів |
| Секрет у git | Компрометація середовища | gitleaks у pre-commit та CI |
| Вразлива залежність | RCE / витік | Trivy у CI, `exit-code: 1` на CRITICAL/HIGH |
| Підміна образу | Виконання чужого коду | cosign keyless підпис + SBOM |
| Реальна виписка у фікстурах | Витік власних даних | `.gitignore` на `tests/fixtures/real_*` |

## Інваріанти, що перевіряються в CI

1. Кожен HTTP-маршрут описаний у `ROUTE_MATRIX`. Новий маршрут без запису
   валить збірку.
2. `admin_session` (обхід RLS) не використовується в роутерах даних —
   статична перевірка вихідного коду.
3. RLS увімкнено **та** `FORCE` для кожної таблиці зі списку `RLS_TABLES`.
4. Роль застосунку не є суперкористувачем і не має `BYPASSRLS`.
5. Cross-tenant запит повертає `404`, а не `403` (403 підтверджує
   існування чужого ресурсу).

## Робота з фінансовими даними

* Суми — цілі числа в копійках; `float` заборонено.
* Сирі файли виписок видаляються через `KOPIYKA_RAW_STATEMENT_RETENTION_DAYS`
  днів після успішного розбору. Нормалізовані транзакції лишаються.
* `audit_log` фіксує доступ до даних із household, actor, IP та User-Agent.
* Експорт і повне видалення даних користувача — ендпоінти, а не ручна
  процедура (тиждень 4).

## Що НЕ реалізовано у v0.1

Чесний перелік, щоб не створювати хибного враження:

* Немає шифрування полів на рівні застосунку (покладаємося на шифрування
  диска / тому провайдера).
* Немає rate limiting на завантаження файлів.
* Немає 2FA (делеговано зовнішньому IdP).
* Backup ще не автоматизовано — заплановано на тиждень 8 разом із
  **перевіркою відновлення**. Бекап без тесту відновлення бекапом не є.
